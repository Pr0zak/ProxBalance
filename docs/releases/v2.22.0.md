This release adds an **Overview**: a dashboard of gauges, charts and the Cluster Map that you pick, drag into place and resize. It also shows each guest's backups, read from Proxmox's own backup logs, and shows affinity partners when you hover a guest on the map.

## Overview

The **Overview / Detailed** switch in the top bar picks which dashboard this browser opens. Detailed is the dashboard you know. Overview (`#/overview`) hides scores, penalties and tables and shows widgets, each a visual with a short caption and a link to the full page:

- **Cluster:** gauges for nodes up, guests running, average CPU and memory (with a tick at your limit), moves in 24 hours, guests backed up and things that need you.
- **Cluster map:** the Dashboard's map, scaled to fit its widget, with a switch for what sizes the bubbles.
- **Nodes:** a tile per node with CPU and memory gauges and a 24-hour line of both.
- **Load, 24 h:** a line per node for CPU, memory or IO wait; touch or hover to read every node at that time.
- **Busy hours:** cluster CPU or IO wait by day and hour for 7 days as a heat map, with the busiest hour named.
- **Memory map:** each node's memory split into its guests, the host and free, with your limit.
- **Busiest guests, Storage, Guests, Room left:** top guests by CPU, memory, network or disk; pools by how full they are; guests per node; how many more 4 GB guests fit.
- **Moves, Backups, Coming up, Automation, What happened:** moves per day for a week, backups per day for two weeks, the forecast chart for the node nearest a limit, every automation check in 24 hours, and a 24-hour time line.
- **Needs you, Waiting for approval, Maintenance:** only things with something to do, with Approve and Skip for queued moves.

**Customize** picks widgets and applies a preset: **Calm** (the default), **Operator**, **Wall** or **Charts**. Type a name under **Save this layout as** to keep a layout; the **Layout** menu switches between presets and saved layouts.

**Arrange** lets you drag a widget's **Move** grip to reorder, and drag its right edge or tap a size to make it ¼, ⅓, ½, ⅔ or a full row wide. Widgets never get narrower than about 300 px: on a smaller screen they take the next size up, and on a phone every widget is a full row. Charts grow with their widget, and the page uses the full width of large screens.

Everything is saved in the browser, so a phone and a wall screen can differ. A browser that has never chosen still opens Detailed, so nothing changes until someone switches.

## Backups per guest

ProxBalance's read-only token can't list backup files, but it can read Proxmox's backup task logs, so ProxBalance now reads those.

- The guest panel has a **Backup** row, for example "16h ago · pbs". It turns amber after 3 days and red when the last backup failed ("Failed 16h ago · last good 3d ago"), with the error behind ⓘ. A guest no backup job covers shows "Not backed up".
- Under it, a 30-day strip shows good, failed and missed days. Days before ProxBalance started recording are dashed, not shown as missed.
- Results are kept for 90 days. How far back the first view reaches depends on how many backup tasks each node still holds.
- What only the backup server knows (snapshot sizes, verification) is not shown.

API: each guest gains a `backup` summary and the summary gains `backup_failed_guests`. New endpoints: `GET /api/guests/<vmid>/backups` (one guest's results) and `GET /api/backups/runs` (every guest's, compact).

## Cluster Map

- **Affinity on hover:** point at a guest in an affinity or anti-affinity rule (tag or pool rule). Its partners get a green (keep with) or red (keep apart) ring, the rest dim, and the tooltip says for each partner whether the rule holds now.

## Smaller fixes

- The top bar fits at tablet width: the Connected badge and GitHub link show from laptop width, the version tag from tablet width.
- The Customize dialog keeps Done in view on a phone.

## Upgrading

Update from the update window (click the version number in the top bar). The updater backs up the database, settings and web files, installs the tested web bundle, restarts ProxBalance and rolls back automatically if it doesn't come back healthy. Backup results appear after the next data collection.
