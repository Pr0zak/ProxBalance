This release makes ProxBalance quieter and more controllable: alerts fire once instead of on every run, automation can ask before moving guests, affinity rules can be soft or required, and new pages check disk health and the install itself.

## Alerts fire once

ProxBalance's own notifications no longer repeat on every collection or recommendation run.

- A threshold alert (a node over its CPU or memory limit, low cluster health) is sent once when the limit is crossed. It resolves only after 3 checks in a row at least 5 points on the good side, so a value hovering around the limit sends one alert, not many.
- "New Migration Recommendations" is sent once while suggestions exist, instead of on every recommendation run (about every 10 minutes). "Recommendations cleared" follows about 3 runs after the last suggestion goes.
- Collector failures, failing safety checks and offline nodes are sent once per episode. A node coming back online still sends "Node Back Online" straight away.
- An exact repeat of any other notification within 2 minutes is dropped.
- **Settings → Notifications** shows the active alerts. Each one can be silenced for 1 h, 8 h, 24 h or until it resolves, either on its own or for its whole type. Active silences are listed with a Remove button.

New settings (under `automated_migrations.notifications`): `alert_resolve_collections` (3), `alert_resolve_margin` (5), `event_dedupe_seconds` (120). See "Alerts, repeats and silences" in `docs/NOTIFICATIONS.md`.

## Semi-automatic mode

A new automation mode, chosen in **Automation → Quick Setup**:

- **Automatic** (default, unchanged): automation moves guests on its own.
- **Semi-automatic**: automation moves guests on its own only for maintenance evacuations and for moves off a node over its CPU (85%) or memory (90%) safety limit. Every other move goes to a **Waiting for approval** list with Approve and Dismiss. Approving runs the move through the same checks as Run Now, re-checked at that moment.

Queued moves look different from moves that ran: a "needs approval" chip, a hollow square in Recent checks, and a "N moves waiting for approval" link on the dashboard. An entry expires after `approval_ttl_hours` (default 24) or when its suggestion goes away. Dry run still wins: nothing moves, and Approve is disabled. A notification type "Waiting for approval" is sent once per guest.

New settings: `automated_migrations.mode` (`automatic` | `semi`), `automated_migrations.approval_ttl_hours`, `notifications.on_queued`.

## Hard and soft placement rules

- **Anti-affinity (`exclude_*` tags) is unchanged**: a node already running a guest with the same tag is never a target.
- **Affinity (`affinity_*` tags) is now soft.** Moving a guest away from its group-mates adds a score penalty (`affinity_soft_penalty`, default 15) instead of pulling the whole group along. Suggestions that split a soft group say so.
- **Required affinity:** tag at least one member `affinity_req_<name>` to keep the old behaviour, where the group moves together.
- **Pool rules:** `automated_migrations.rules.pool_rules` can treat a Proxmox pool as an affinity or anti-affinity group, optionally required.
- **Automation → What to Migrate → Guest Rules** lists every rule as Hard or Soft and whether it holds right now. **Enforce now** shows the moves that would fix broken hard rules and asks before running them (dry run respected).

> **Upgrading:** before v2.19 every `affinity_*` group was required. If you rely on a group moving together, retag one member `affinity_req_<name>`.

## Disk health (SMART)

The node side panel shows one line for the node's disks, such as "Disks: 6, all passed SMART". A disk that fails SMART, reports unknown health or has 20% of its life left or less gets its own line, and a failed disk adds a red "⚠ SMART" marker next to the node in the Nodes table. The data comes from the Proxmox API (`/nodes/<node>/disks/list`) on each collection and needs Sys.Audit, which the standard token has.

## IO pressure

ProxBalance now collects Linux IO pressure (PSI) from Proxmox 9's RRD data for nodes and guests: the share of time tasks waited on disk. The node side panel shows it under IOWait. A sustained 7-day IO pressure over 30% adds a score penalty (10 points, or 25 over 50%), except on nodes marked IOWait-exempt. On Proxmox 8, which has no PSI, nothing changes.

## Diagnostics

**Settings → Diagnostics** runs read-only checks and shows one line each: Proxmox API reachability and latency, each node, cluster quorum, token permissions (naming what is lost without each one), storage state per node, the collector, timers, the database, cache age and updates. Details are behind each line, and **Copy as text** builds a report with secrets removed. API: `GET /api/diagnostics`.

## Quick search

Press **Ctrl+K** (Cmd+K on a Mac) or **/**, or use the search button in the top bar, to jump to any guest, node or page. Choosing a guest or node opens its side panel. It works from the keyboard alone and on phones.

## Fixes

- The expert IOWait penalty fields in Settings edited settings that didn't exist. They now edit the real Over 10% / 20% / 30% penalties.
- Opening a side panel from an address with no tab (`#/dashboard/guest/100`) now works, and switching between panels keeps the address correct.

## Upgrading

Update from the update window (click the version number in the top bar). The updater backs up the database, settings and web files, installs the tested web bundle, restarts ProxBalance and rolls back automatically if it doesn't come back healthy. Disk health and IO pressure fill in after the next collection.
