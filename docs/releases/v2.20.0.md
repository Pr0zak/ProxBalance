This release adds a record of every change, a plan for updating Proxmox one node at a time, planned moves drawn on the Cluster Map, and a full-screen view for a wall monitor.

## Change log

**Automation → History & Logs → Change log** lists what changed and who or what changed it, newest first:

- Migrations: manual moves, batches, rollbacks, evacuations, "Enforce rules now", and automation's own moves and failures.
- Approvals: queued moves approved or dismissed (semi-automatic mode).
- Settings: automation on/off, dry run, mode, maintenance on/off, and any other setting saved. Only the names of the changed settings are recorded, never their values, so secrets never reach the log.
- Tags added or removed, alert silences, Run Now, service restarts.
- Updates started, finished, failed or rolled back.

Each line shows the time, whether it came from a person, automation or the system, and one sentence. Filter by source or by type; tap a line for details. Past automatic migrations are imported from the migration history on first use. Entries are kept for 180 days. For requests from the browser, the client address is recorded.

API: `GET /api/audit-log?since=&source=&action=&limit=&before=`.

## Rolling update plan

A new card on Insights, after "What if a node fails?", plans updating or rebooting the nodes one at a time. It only plans: it never migrates, updates or reboots anything.

- **Quorum:** votes present, votes needed, and whether any single node can go down. Two-node clusters and QDevices are flagged.
- **Order:** nodes with the fewest guests to move go first; the node running ProxBalance goes last.
- **Each step:** where each running guest would go (respecting storage, memory up to 95%, hard placement rules and HA rules), which guests must shut down (passed-through hardware or node-local bind mounts), target memory after the moves, and how much node-local disk data would be copied. A node that has been updated is used as a target for later steps.
- **Start maintenance on <node>** opens that node's panel and the existing maintenance flow.

API: `GET /api/rolling-update/plan[?order=vega,draco,...]`.

## Planned moves on the Cluster Map

Current suggestions are drawn as dashed arrows from source to target node, one per pair, with the number of guests at the middle. Hover or tap the number for the guest names. Moves waiting for approval in semi-automatic mode are dotted blue. Arrows disappear once their moves run. The map's **Plan** button turns them off, and they are now on by default.

The map opened from the dashboard's options button now gets suggestions and headroom too, so it shows the plan and the headroom badges.

## Wall-monitor mode

The new full-screen button in the top bar (large screens), or the address `#/wall`, opens a view for a monitor on the wall: the summary row, the Cluster Map, CPU per node and automation status with the last 24 hours of checks. It fills the screen at 1080p and 1440p without scrolling, keeps the screen awake where the browser allows, and has no menus or panels. Press Esc, leave full screen, or use the Exit button that appears when you move the mouse. On a phone it becomes a normal scrolling page.

## Upgrading

Update from the update window (click the version number in the top bar). The updater backs up the database, settings and web files, installs the tested web bundle, restarts ProxBalance and rolls back automatically if it doesn't come back healthy. From this version on, updates themselves appear in the change log.
