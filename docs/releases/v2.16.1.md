The dashboard's suggestions and automation section are rebuilt to show what is happening at a glance, with the detail one tap away. This is also the first release production installs receive through the new release-only updater.

## Suggestions

Each suggestion card is now three lines:

- **The guest and one status chip:** "Ready · will run next check", "Ready · dry run", "Waiting 2/3 runs", "Blocked: inflow cap", "Blocked: HA rule", "Automation paused" or "Manual only". Tap the chip for a one-line explanation.
- **Before → after bars** for the node the guest leaves and the node it goes to, on the metric that drives the move (CPU, memory or IO wait), using the same predicted values as the batch-impact strip. When there is no prediction, the card shows only the current value.
- **One reason**, such as "pve5 CPU rising 4.5%/day", and a **Details** toggle with confidence and risk, the reasons, how many automation runs have seen it, guest size, warnings and the migrate command.

The "+56" improvement points, the ROI figure and the repeated explanation paragraph are gone.

## Automation section

The automation banner on the dashboard now answers three questions without prose:

- **What did the last check do?** One line and a chip: "Last check 3 min ago · would move · sonarr pve3 → pve6". Dry runs are never shown as moves; the banner shows the last *real* move separately.
- **What has automation been doing?** A strip of squares, one per check over the last 24 hours: grey for nothing to do, violet for waiting, amber for would move, filled for moved, red for failed, hatched for skipped. Tap a square to see that check.
- **Did past moves help?** "Helped 8 of 10", then one line per move: guest, from → to, day, the old node's CPU before → 24 h after, and the change (▼17 green, ▲14 red). Tap a row for the full numbers. On phones this list starts collapsed.

When a check holds guests back, they are grouped into one line ("19 guests waiting their turn (one move per check)") instead of a chip each, and each check's Details is one compact table: guest, route, result, confidence, target score.

## Other changes

- ProxBalance now keeps the last 300 automation runs instead of 50, so the 24-hour strip has enough history at short check intervals.
- A seen count can no longer read above its requirement (runs recorded before v2.16.0 could show "6 of 3").
- CI runs every JavaScript test file, not only the schedule tests.

## Upgrading

Click the version number in the top bar and update. On v2.16.0 the update runs through the new updater: it backs up the database, settings and web files, installs the tested web bundle, restarts ProxBalance and rolls back automatically if it doesn't come back healthy.
