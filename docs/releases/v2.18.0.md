This release makes it easier to see how load sits across the cluster: one chart with every node, a role marker on each node that is giving or receiving guests, and forecast charts that show when a node will reach its limit.

## One chart for every node

The Charts tab now opens on a single chart with one line per node on a shared time axis, for one metric at a time (CPU, Memory or IO wait). The old per-node grid is one tap away under **Per node**, and the choice is remembered. The three-card "By metric" view is replaced by this chart.

- Lines use the raw samples at 1h and 7d, 2-minute averages at 6h, 5-minute averages at 1d, and coarser averages from 30d up (2 hours, 6 hours, 12 hours, 1 day). The average in use is named once under the chart.
- The recommendation threshold for the metric is a thin dashed line.
- The node names under the chart show or hide each line; hovering one highlights it. Tapping a line highlights that node and shows only its migration markers. With **Min/Max** on, the highlighted node also gets its min/max band (visible where samples are averaged).
- One line under the chart gives the spread right now, for example "Spread now: 24 pts (pve6 26% → pve3 50%)".
- A node that was offline shows a gap, never a line drawn across the outage.

On phones only the metric control stays above the chart; layout, period and overlays sit behind one **Options** button. The Cluster Health card's help text moved behind an info button, and its legend fits on one line.

## Node roles

Each node that suggestions move guests off or onto now carries one marker on the Nodes table, the Cluster Map and the node side panel:

- **Giving** (up arrow) or **Receiving** (down arrow), with the number of guests moving. A node that is both takes the net direction; the tooltip keeps both counts and names the guests.
- **Maintenance** (wrench).

Nodes with no suggested moves carry no marker. A one-line legend under the table and the map lists only the roles present. This replaces the orange "→N" and green "←N" badges next to node names.

## Forecast charts

The Forecasts card on Insights draws one chart per node metric that is heading for its limit within 30 days: history, a dashed line continuing the trend, a marker at now and a dashed line at the limit. Each chart has one headline, for example "pve5 memory reaches 80% in about 12 days"; medium-confidence fits say "rough estimate", and the fit details are behind a Details toggle. At most three charts show, soonest first, with **Show all** for the rest. When nothing is heading for a limit the card is one line.

The IO wait forecast now uses the configured IO wait threshold. It used to fall back to 30%, while recommendations use the configured value.

API: `GET /api/trends/nodes?series=1` adds the chart data to each node metric.

## API changes

- `GET /api/analyze` and `GET /api/cluster-summary` no longer start a collection when no data has been collected yet. They return 503 with `no_data: true`; start a collection with `POST /api/refresh`. The dashboard's empty state now has a **Collect now** button that does this and waits for the first data.
- The unreachable duplicate `GET /api/score-history` handler is removed. The served route (`limit`, `bucket`) is unchanged.

## Upgrading

Update from the update window (click the version number in the top bar). The updater backs up the database, settings and web files, installs the tested web bundle, restarts ProxBalance and rolls back automatically if it doesn't come back healthy.
