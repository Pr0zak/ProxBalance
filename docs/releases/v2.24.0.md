This release replaces the dashboard's cluster health tile, which said how much room was left but not whether the load was even.

## Cluster health: Capacity and Balance

- **Two numbers instead of one.** **Capacity** is the headroom on the busiest node, the number the tile showed before. **Balance** is 100 minus the larger gap between the most and least loaded node, for CPU or memory. Each has a dot: green, amber or red.
- **Balance agrees with the recommendations.** It uses the same readings the recommendation engine uses to decide whether the cluster is balanced, so CPU held by guests that can't move (a NAS, for example) is left out. Green means the nodes are within 8% of each other and none is too full. Amber means the load is uneven but no move is worth making. Red means a node is too full or moves are suggested.
- **New panel when you click the tile.** One row per node with its capacity and a CPU and a memory bar. The most loaded node is amber, the most free is blue and a node that's too full is red. Each bar marks the cluster average and the maximum allowed. Click a row for that node's capacity breakdown.
- On phones the status line shows both numbers.
- The attention strip says a node is "low on capacity" instead of "short on room".

## API

- `GET /api/analyze` and `GET /api/cluster-summary` return a new `cluster_balance` object. See `docs/API.md`.

## Upgrading

Update from the update window (click the version number in the top bar). The updater backs up the database, settings and web files, installs the tested web bundle, restarts ProxBalance and rolls back automatically if it doesn't come back healthy.
