This release makes every screen shorter and easier to read on a phone, fixes two automation settings that did nothing, stops ProxBalance from offering moves that Proxmox would refuse, and improves the forecasts, the comparison chart and the Cluster Map.

## Shorter text, detail one tap away

Long explanations wrapped to four or five lines on a phone. Each fact now shows as a short line; the full explanation is behind a small ⓘ that you tap (hover works too on a desktop). On a 390 px phone, no explanatory text wraps past two lines unless you open it.

- **Node panel:** the header shows the role and its count ("Giving 8") and one status line ("Online · up 12d · 9/9 running") instead of listing every guest. IO pressure, what happens if the node fails, CPU that stays put and disk health are short label/value rows, for example "If it fails: all 9 restart · busiest lyra 80% mem" and "sda: SMART failed".
- **Guest panel:** the verdict is a title and one line ("Won't move now: orion is under the trigger"); the numbers and reasons are behind **Why**.
- **Dashboard:** the migrate confirmation says "Why: draco CPU over 60%"; the evacuation notes, conflict and wave lines, legends and cluster-health box are shorter.
- **Automation, Insights and Settings:** every option has a one-line description, with the how and why behind ⓘ. The Automation tabs are 230–600 px shorter on a phone, and the node-failure summary on Insights is one line instead of nine.
- **Evacuation plan on a phone:** each guest is a card with its target and action menus instead of an eight-column table that ran off the screen.

No warnings were removed.

## Automation settings that now work

- **Turn off automation on a failure** (`safety_checks.pause_on_failure`): after a real move fails, the run stops and automation switches itself off until you turn it back on. The change log says "Automation turned off: the move of <guest> failed".
- **Allow container restarts** (`rules.allow_container_restarts`): switching it off makes automation skip running containers, which can't live-migrate. Manual moves and stopped containers are unaffected. A missing setting means allowed, which is what every install did until now, and the toggle now shows it that way.
- **A failed move is no longer retried in the same run.** With "Stop the batch on a failure" off, a guest whose move failed was tried again on each of the run's remaining slots.

## Moves Proxmox would refuse

- **PCI and USB passthrough:** a VM with a passed-through GPU or USB device and no passthrough disk is now marked **Pinned** and is never suggested. Before, it showed as Movable and a suggested move failed in Proxmox. Containers with only a device node (`devN`) stay movable.
- **Host folder mounts:** Proxmox won't migrate a container with an unshared bind mount, with or without a restart. The guest panel no longer offers a move for it and the map's drag preview blocks it. The advice now says to mark the mount `shared=1` once the folder exists on every node (with the `pct set` command filled in), or to remove the mount, move the container and add it back.

## Forecasts

- **Nodes already past a limit:** a node past its limit and still rising was dropped as if it were flat, so Insights said "No node is heading for a limit". It now says, for example, "lyra memory is past its 70% limit and reaches 100% in about 10 days".
- A trend is projected at most twice as far ahead as the history it was fitted on (30 days at most), so a 24-hour window looks 2 days ahead, not 30.
- Rises that stay under the limit get one line each, and weak fits that would cross are named instead of dropped silently.

API: `forecast` in `/api/trends/nodes` gains `status`, `days_to_full`, `max_horizon_days` and `window_days`; `horizon_days` is the horizon actually used.

## Charts and map

- **Comparison chart:** the spread is read from the last plotted point, so it matches the lines. The Min/Max band has real width at 1 h (it was zero there) and turns on by itself when only one node is visible.
- **Cluster Map:** long suggested-move arrows sit on separate heights with their own endpoints and number badges. Guests tagged `ignore` get an eye-off badge.
- **Recent checks strip:** labelled Yesterday / Today, with a gap at midnight.
- **Node panel:** a node in maintenance no longer shows "Base load 999999" and a red 0; it shows a dash and why it isn't scored.

## Documentation and demo

- The documentation is updated for v2.18–v2.21, every API endpoint is documented, and all screenshots are new.
- Screenshots come from a demo cluster with invented names (`tools/demo/`): a fake Proxmox API with five nodes and 42 guests, 90 days of history, broken and holding placement rules, pinned, ignored and host-folder guests, and a move waiting for approval. See "Demo Cluster and Screenshots" in `docs/CONTRIBUTING.md`. It refuses to run on a host not named `proxbalance-staging` unless told to.
- Tests, code comments and release notes no longer contain real host names or addresses. `update.sh` now requires the container ID instead of defaulting to one.

## Upgrading

Update from the update window (click the version number in the top bar). The updater backs up the database, settings and web files, installs the tested web bundle, restarts ProxBalance and rolls back automatically if it doesn't come back healthy. The PCI/USB pinning appears after the next data collection.
